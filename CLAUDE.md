# Operating rules for Claude in this repo

This is an experimental sandbox repo with no real data. The owner wants Claude to run autonomously.

- Do not stop to ask for decisions. Pick the most sensible option, act, and record it.
- Log every non-obvious choice (what, why, alternatives skipped) as a dated entry in `DECISIONS.md`.
- Keep a running `TASKS.md`: what is in progress, what is done, what comes next. Pick up from it at the start of each session, since cloud containers are ephemeral and only what is committed survives.
- Commit and push after each meaningful step so work is never lost when a container is reclaimed.
- Only stop for things that actually need the owner: a missing credential, an external account action, or spending real money.

## Paid APIs (Treg connector)
- Treg tools (`mcp__Treg__*`) are pre-approved in `.claude/settings.json`; call them without asking.
- Before any job that makes many calls, run `mcp__Treg__balance` and estimate cost from `catalog_get`.
- Log spend in `DECISIONS.md` (what, how many calls, $).
- No top-up is planned (owner, 2026-11-09). Keep a $0.10 reserve: if a job would take the balance below it, switch that job to free audio (`edge-tts` on the PC, code-made music) and keep going. Note it in `DECISIONS.md`.

## Reel loop rules (owner, 2026-11-09)
- All visuals are generated by code. Audio may come from any source.
- The owner's PC (`gamer@arch` over Tailscale, helper `scripts/pc`) is a sandbox for downloads, transcription and rendering. Work inside `~/reels-loop` there.
- The loop plan is `LOOP.md`. Do not start it without the owner's "go" in the session.
